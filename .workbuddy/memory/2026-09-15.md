### 关键坑：.gitignore 里的全局 `*.png` 会挡住图标
- 仓库 `.gitignore` 有 `*.png`（用于排除截图），新生成的 mipmap PNG 会被静默忽略、根本进不了提交。
- 需要在文件末尾加例外（父目录未被排除，负向规则才生效）：
  ```
  !app/src/main/res/mipmap-*/ic_launcher.png
  !app/src/main/res/mipmap-*/ic_launcher_round.png
  ```
- 验证手段：`git status --porcelain -uall`，确认 PNG 以 `??` 列出而不是被吞掉。

### 可复用：矢量图标栅格化流程
- 脚本：`tools/gen-icons/gen_icons.py`（矢量源 `tools/gen-icons/ic_launcher_foreground.xml` 同目录留档）。
- 原理：VectorDrawable 的 `android:pathData` 与 SVG 的 `d` 语法完全兼容，`<group>` 的
  pivot/scale/rotate/translate 能换算成等价的 SVG transform，所以改用无头浏览器渲染即可得到矢量级清晰的位图，
  不需要装 cairo 之类的原生依赖。
- group 变换换算（重点）：Android 的 `postTranslate/postScale` 是**左乘**语义（与 iOS 相反），
  变换链为 `T(translate+pivot) · R(rotation) · S(scale) · T(-pivot)`，pivot 点保持不动。
  对应的 SVG 写法：`transform="translate(tx+px,ty+py) rotate(r) scale(sx,sy) translate(-px,-py)"`。
  ⚠️ 顺序写反会导致图形偏移（把 pivot 当成普通缩放原点就会算错位置）。
- 渲染命令（Edge/Chrome 无头，WSL 之外直接可用）：
  ```
  msedge --headless=new --disable-gpu --hide-scrollbars --force-device-scale-factor=1 \
         --default-background-color=00000000 --window-size=432,432 \
         --screenshot=out.png file:///.../icon.html
  ```
  `--force-device-scale-factor=1` 必须有，否则系统 DPI 缩放会让输出尺寸翻倍。
  `--default-background-color=00000000` 用于圆形变体保留透明角。
- 环境：本机 Edge 在 `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`；
  Pillow 装在 `C:\Users\Administrator\.workbuddy\binaries\python\envs\default`（用于校验输出尺寸）。

## 新增「退出应用」功能

- 入口位置：**设置页最底部**一张卡片（红色电源图标 + 说明 + 全宽危险色按钮），点击弹 `ConfirmDialog` 二次确认后退出。
- 未加到顶部菜单栏；如果用户觉得藏太深，可在 `res/menu/main_menu.xml` 再补一个 `menu_exit` 项复用同一逻辑。
- 新增 `com.carassistant.util.AppExit`，退出顺序**不能改**：
  1. `stopService(MonitorService)` —— 性能监控是**前台服务**，不先停就杀进程的话系统会把它重新拉起，表现为"退出了但悬浮窗又冒出来"；
  2. `NotificationManagerCompat.cancelAll()` —— 清掉前台服务通知与 U 盘提醒；
  3. `finishAndRemoveTask()` —— 关掉整个任务栈（含压栈的设置页/详情页）；
  4. `Handler.postDelayed(250ms)` 后再 `killProcess(myPid()) + System.exit(0)` —— 留时间让 stopService 真正走完 `onDestroy`。
- 复用件：`ConfirmDialog.show(...)` + `R.drawable.ic_power`（新建的 24dp 电源矢量，dialog 里由 `android:tint="#FFFFFF"` 染白）。
  32 位色值写法沿用项目惯例 `#FF000000`。

## 图标换成用户提供的 192x192 成品设计稿（提交 fd93494）

- 用户给了 `Downloads/192.zip`（内含 `192.png`，192×192 RGBA，蓝色圆角方块 + 白色车形），要求用它做图标。
- 已归档为**唯一设计源**：`tools/gen-icons/source/ic_launcher_source.png`。
- **密度基准变了**：从原来的 108dp 自适应画布（108/162/216/324/432）改成传统图标标准 48dp 基准
  （**mdpi 48 / hdpi 72 / xhdpi 96 / xxhdpi 144 / xxxhdpi 192**）。
  理由：设计稿是自带圆角方块的**完整图标**（不是自适应前景层），192px 正好是标准 xxxhdpi 尺寸；
  若按 108dp 画布就得把 192 放大到 432，会发虚。
- 圆形变体（roundIcon）用超采样圆形遮罩裁切：先画 4 倍大的圆形 mask 再缩回来，边缘才平滑。
- 设计源内容 bbox = (0,0,192,192)，满画布无留白，桌面显示不会被无谓缩小。
- ⚠️ 分辨率上限就是 192px。若车机 launcher 把图标放大到 192 以上会发虚 —— 需要的话让用户提供
  512/1024 的设计稿再重跑脚本，**不要**直接上采样。
- `gen_icons.py` 已重构：优先读位图设计源；找不到才回退到原来的矢量渲染路径（无头浏览器）。
- ⚠️ `.gitignore` 的 `*.png` 又咬了一口：设计源 `tools/gen-icons/source/*.png` 需要单独补例外。

## Gradle 缓存锁的彻底解法（比 `--stop` 更管用）

- 现象：`gradlew assembleDebug` 启动阶段直接失败，报
  `Could not create service of type FileAccessTimeJournal` →
  `java.io.FileNotFoundException: C:\Users\Administrator\.gradle\caches\journal-1\journal-1.lock (拒绝访问)`。
- 之前记录的办法是 `gradlew --stop`，但这次**连跑两次 --stop + 重编都无效**，`--stop` 还报 "No Gradle daemons are running"。
- 真正的原因是 `.gradle\caches\journal-1` 里残留了一个**僵死的锁文件**（file-access.bin / journal-1.lock）。
- **有效解法**：直接删掉整个缓存目录再重编，立刻成功（Gradle 会自动重建）：
  ```powershell
  & .\gradlew.bat --stop
  [System.IO.Directory]::Delete("$env:USERPROFILE\.gradle\caches\journal-1", $true)
  & .\gradlew.bat assembleDebug
  ```
  删的是 Gradle 的**文件访问时间缓存**，不是项目数据，安全。
- 排查顺序：① `gradlew --stop`；② `Get-Process java` 看有无残留守护进程；③ 删 `journal-1` 目录。
