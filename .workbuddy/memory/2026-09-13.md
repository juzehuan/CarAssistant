## 修复 U 盘识别（提交 3ce8250）

- 现象：车机 Android 8/9，插 U 盘后文件管理页完全看不到 U 盘条目。
- 根因三条叠加：
  1. `StorageUtil.getAllStorages()` 只反射隐藏 API `StorageManager.getVolumeList()`，targetSdk 34 下受隐藏 API 限制影响容易失败；
  2. U 盘判定只看路径含 `usb`/`udisk`/`/mnt/media_rw/`，而 Android 8/9 U 盘挂在 `/storage/XXXX-XXXX`，三个条件全不成立；
  3. `FileFragment.refreshStorages()` 用 `total <= 0` 静默过滤，StatFs 失败就直接吞掉条目。
- 修法（可复用的 Android 存储枚举套路）：
  - 三级枚举：公开 `getStorageVolumes()` → 反射 `getVolumeList()` → 扫 `/storage`、`/mnt/media_rw`、`/mnt/usb_storage`、`/mnt/udisk` 等根目录。
  - 路径归一化：`/mnt/media_rw/<seg>` ↔ `/storage/<seg>` 取可读的那个（前者普通应用无权访问）。
  - U 盘判定：路径关键字 + `/proc/mounts` 块设备 major（8/65-71/128-135 = SCSI 即 U 盘；179/259 = MMC 即 SD 卡）+ `/dev/sdX`。
  - 挂载判定：`Environment.getExternalStorageState(File)` + `/proc/mounts` 独立挂载点校验，避免拔掉后残留的空壳目录被误判成卷。
  - 路径去重（LinkedHashSet），并保证内部存储一定在列表首位。
- 顺带：扫描改异步（原在主线程跑 StatFs + root dd，有 ANR 风险）；动态注册 MEDIA_* 广播实时刷新；头部加「重新扫描」按钮；`UsbReceiver` 的跳转 extra 由无效的字符串 `"tab"` 改为 `MainActivity.EXTRA_NAV_ID`。
- 排查线索：`Log.d(TAG="StorageUtil")` 会打印每个卷的来源（api/hidden/scan）与 usb 判定结果，现场可用 logcat 直接看。
